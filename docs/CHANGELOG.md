# История версий — AMT Chat

Краткая, читаемая история релизов. Технический детальный changelog для
отдельных версий хранится в `backend/changelog.json` (используется
автообновлением и экраном «Справка → Апдейты»). Формат — «версия: что
изменилось», по одной строке на изменение, без эмодзи.

Версии идут от старых к новым.

---

## 1.1.6 — текущий (2026-11-28)

- Критический фикс: ИИ реально видит прикреплённые фото и файлы (Ctrl+V и
  скрепка). Ранее глобальный список вложений очищался ДО загрузки на бэкенд,
  поэтому `uploadAttachments()` обрабатывал пустой массив и ни один файл не
  попадал в папку вложений — байты не доходили до модели, и она отвечала
  «не вижу фото». Теперь в sendMessage() передаётся отобранный срез
  `_filesForThisMessage` (созданный до очистки), и файлы реально
  загружаются на бэкенд.

## 1.1.5 — (2026-11-28)

- Вложения: ИИ снова реально видит фото и файлы, прикреплённые через
  Ctrl+V и через скрепку. Фото/файл больше не теряется, если сохранённый
  абсолютный путь устарел (приложение пересобрано/перемещено) — бэкенд
  теперь перерезолвит имя файла по актуальной папке вложений (включая
  тайм-префикс {ts}_{name}), а не молча выбрасывает вложение.
- Вложения: пустой или «octet-stream» MIME больше не превращает картинку в
  плейсхолдер — тип угадывается по расширению на фронтенде (при вставке и
  загрузке) и на бэкенде, поэтому фото попадает в vision-ветку и ИИ видит
  пиксели.
- Анти-галлюцинация: если ни одно изо��ражение НЕ удалось встроить (нет
  пиксельных данных), но пользователь ссылается на фото/файл, модель
  получает явную подсказку не выдумывать содержимое и попросить повторно
  прикрепить файл (исправлен случай, когда на XLSX ИИ описывал несуществующее
  фото).
- Перегенерация: для старых сообщений без сохранённых путей теперь
  резолвятся реальные вложения по именам (POST /api/files/resolve), а не
  отправляются голые строки.

## 1.1.4 — (2026-11-28)

- Перегенерация ответа: больше нет ошибки «1 validation error» —
  фронтенд отправляет вложения как словарь {path, filename, mime_type},
  а не голые имена; бэкенд также теперь терпимо резолвит строковые
  вложения по FILES_DIR (включая тайм-префикс {ts}_{name}).
- Перегенерация: под ответом ИИ теперь появляются стрелки навигации по
  версиям (ранее предыдущий ответ терялся — target.content обнуляли до
  того, как записать его в _versions).
- Вложения: ИИ снова видит фото и файлы при перегенерации и на старых
  сообщениях (сохраняется точный путь _attPaths при отправке;
  /api/files/resolve резолвит имена в пути).
- Редактирование сообщения: новые файлы, добавленные при правке, реально
  загружаются на бэкенд (uploadSingleFile) и сохраняются в _attPaths;
  кнопка «X» теперь удаляет файл по имени, а не по устаревшему индексу.
- Файлы в сообщении: добавлено GET /api/files/{name} — превью-карточки
  файлов пользователя больше не падают на 404.
- Vision: даже в tool-calling режиме модель получает короткую подсказку,
  что изображения встроены и она их видит.
- Медиа-анализ: ИИ видит **все** типы вложений — фото, видео, аудио и
  обычные файлы. Видео разбирается в base64-кадры (видит картинку), аудио —
  в транскрипт (STT), файлы — в текст/картинки. Если MIME пустой или
  «octet-stream», бэкенд угадывает тип по расширению (видео/аудио/картинка
  попадут в правильную ветку и ИИ их увидит, а не получит плейсхолдер).

## 1.1.3 — (2026-11-28)

- Вложения: картинки больше не обрезаются — base64 data-URL проходит
  целиком, модель видит фото (ранее обрезка на 120 000 символов ломала
  регулярку встраивания и ИИ видел только имя файла).
- Вложения: аудио/видео и PPTX тоже пропущены из текстовой обрезки — их
  output содержит base64-кадры/транскрипт, обрезка которых ломала
  встраивание image_url.
- PPTX: слайды теперь растеризуются в PNG и показываются модели (не
  только текст). Движок: PowerPoint COM (если установлен Office) →
  LibreOffice headless (soffice/libreoffice на PATH или в
  `AMT_DATA_DIR`) → fallback на текст. До 200 слайдов, каждый PNG до 8 МБ.
- PPTX: `media_understanding.render_pptx_slides(path)` — публичная
  функция, возвращает список PNG-байтов; тестируема.

- MCP: метод `MCPManager.ensure_connected(server_id)` — гарантирует живую
  сессию перед вызовом инструментов (используется в `main.py` и
  `command_engine.py`); до этого отсутствовал, и включение сервера через
  `/api/mcp/servers/{id}/enable` падало с `AttributeError`.
- MCP: синхронная точка входа `command_engine.execute_command_request`
  корректно запускает корутину `ensure_connected` — `asyncio.run()` без
  активного цикла или `loop.create_task()` внутри асинхронного контекста.
- MCP: кнопка «Запустить / Остановить» в «Настройки → MCP-серверы» и в
  «Хранилище» — переключатель состояния по `connected`; `is_connected()`
  отдаёт живой флаг в `/api/mcp/servers`.
- MCP: кодинг-сервер (`AMT_CODING`) теперь подключается через
  `AMT_BACKEND_MODE=coding` в entrypoint `main.py`; добавлен `main()` в
  `coding_mcp_server.py`; frozen-пресет передаёт режим через env, а не через
  аргумент скрипта (PyInstaller-bootloader его игнорирует).
- MCP: фикс 500-ошибки на `/test` медиа и writer — латентный `NameError`
  (`log` вместо `logger` в `_write_media_creds`); creds-файл пишется в
  `%APPDATA%\AMT Chat\media_creds.json` (writable), preset env получает
  `AMT_MEDIA_CREDS_FILE`.
- Темы: свотч/селект темы теперь обновляет поля редактора тем через
  `window.AMTThemeEditor.onThemeChange`; все `input[type=color]` получили
  нейтральный светлый фон (`#e9edf2`) и `color-scheme: light`, чтобы
  нативный swatch-виджет показывал реальный цвет, а не чёрный.

## 1.0.8 (2026-11-26)

- Нативный LLM tool-calling: модель получает JSON-схемы инструментов и сама
  выпускает `tool_calls`; бэкенд исполняет через `ToolRegistry` (до 5
  итераций), `[[GEN]]`-токены — страховка.
- `ToolRegistry` (`ai_engine/tool_registry.py`): единая точка регистрации/
  выполнения — нативные media/file-инструменты + внешние MCP; результаты
  обрезаются до 4 КБ.
- MCP-менеджер (`ai_engine/mcp_manager.py`): STDIO-процессы или HTTP,
  инструменты с префиксом `mcp__<server>__<tool>`, таймаут 30 с.
- Безопасность MCP: env-переменные шифруются Fernet (`mcp_key.key`, 0600);
  инструменты MCP по умолчанию требуют подтверждения.
- REST `/api/mcp/servers`: CRUD + test/enable/list-tools + shutdown;
  ленивая инициализация + atexit-очистка.
- UI: страница «Настройки → MCP-серверы» + список в «Хранилище»;
  карточки tool-call'ов в чате.

## 1.0.6 (2026-11-25)

- Голосовое управление: полный цикл wake-word → VAD-запись с авто-остановкой
  по тишине → STT → LLM → TTS + чат.
- Wake-word — локальный Vosk по WebSocket `/ws/wake-word` (16 kHz mono,
  офлайн, без API-ключа); fuzzy-матч + алиасы.
- Локальный Vosk-STT: `/api/stt-local`, авто-загрузка модели (~50 МБ) при
  первом запуске; `/api/voice/status` для прогресса.
- STT-фолбэк: облачный недоступен → локальный (и наоборот).
- TTS: браузерный `speechSynthesis` (бесплатно) или облачный; микрофон
  глушится во время речи (эхо-защита).
- API-ключи шифруются в `secrets.bin` (Electron safeStorage/DPAPI), не в
  `settings.json`.

## 1.0.0 — первый официальный релиз (2026-11-24)

Полный набор функций базового продукта:

- Чат с любой OpenAI-совместимой или локальной моделью: Base URL + API-ключ
  + имя модели, мульти-ключи с авто-переключением при 429 (приоритет или
  round-robin).
- Агенты: роль + системный промпт + модель/температура + набор скиллов. Ядро
  (Веб-агент, Глубокий аналитик, Без фильтров) создаётся автоматически;
  свои агенты — через UI или импортом `agents.json` / JSONL.
- Скиллы: переиспользуемые инструкции, подключаются к агенту или в чате
  отдельно; импортируются тем же файлом.
- Личности: готовый профиль (ключ + модель + агенты + скиллы + оркестратор),
  создаётся в UI или импортом JSONL (по одной сессии на строку).
- Оркестратор: контроль контекста (сжатие истории при переполнении окна),
  контроль дрейфа роли, умное сохранение чата по порогу, мониторинг
  (з��держка/ошибки/среднее по 100 запросам).
- Память: лонг-терм факты между чатами, автоматически подставляются в
  системный промпт; лимит и очистка в настройках.
- Медиа-генерация: `[[GEN:image|…]]`, `[[GEN:video|…]]`, `[[GEN:audio|…]]`,
  `[[GEN:file|…]]` — готовый элемент вставляется прямо в сообщение; работает
  с любым провайдером через OpenAI-совместимые эндпоинты.
- Безопасные инструменты (tool-calling): чтение/запись файлов, создание
  папок, листинг каталогов, запуск команд — только в выбранной рабочей
  папке; запись/команды требуют подтверждения, команды — только из белого
  списка; всё логируется.
- Медиа-плеер: YouTube/Twitch embeds, `.mp4`/`.m3u8`, фото, аудио — в
  чате/плеере, fullscreen, фильтры; сайты, блокирующие iframe, открываются
  во встроенном frameless-браузере.
- Голосовой чат: STT + TTS через любой провайдер, отдельное поле для
  STT-модели.
- Система расширений: папки в `extensions/` с `manifest.json` (+ опц.
  `index.js` / `backend.py`) — без перекомпиляции приложения.
- Справка: отдельная страница — об app, хаб расширений, гайд «как писать»,
  история обновлений.
- Хранилище: просмотр и экспорт всех данных (агенты/скиллы/ключи/темы/
  расширения/чат).
- Логи: дашборд событий по API / оркестратору / инструментам с фильтрами.
- Desktop: Electron + встроенный Python-бэкенд (sidecar, PyInstaller-бандл),
  NSIS-инсталлятор для Windows.
- Темы: готовые + своя (градиент), шрифт и фон, язык интерфейса (RU/EN).

## Предшествующие версии (до 1.0.0)

До первого официального релиза проект использовал другую схему нумерации
(1.5.x → 1.4.x → … → 0.8.0), которая была сброшена при вводе 1.0.0. Полный
лог этих версий доступен в `backend/changelog.json` (поле `releases`).
Кратко: медиа-универсализация, файлы с исходником, понятные ошибки
(1.5.x); связка IPC, оптимизация, тесты, чистка (1.5.2).
