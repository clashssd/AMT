Docs — примеры и справочник

Подробные примеры. В каждом файле только промпты и ключи подставляете свои — остальное опционально. Импорт: «Агенты/Скиллы» → «Импортировать из файла».

1. Агенты + скиллы
agents[].systemPromptроль агента — подставляете свой текст
показываемое имя: agents[].name · модель: agents[].model · креативность: agents[].temperature (0–2) · группа: agents[].group · параллельно: agents[].parallel · макс. ответ: agents[].maxTokens · окно контекста: agents[].contextWindow · свой Base URL: agents[].baseUrl · привязанный ключ: agents[].keyId · свой оркестратор: agents[].orchestrator ("base"/"custom") + agents[].orchestratorRules
skills[].promptинструкция скилла — подставляете свой текст
skills[].nameвидимое имя скилла в списке
опционально у скилла: skills[].enabled (по умолчанию true) · skills[].group
{
  "agents": [
    { "id": "architect", "name": "Архитектор",
      "systemPrompt": "Ты — senior-архитектор. Оценивай решения, давай trade-offs.",   /* <- ваш промпт */
      "model": "ВАША-МОДЕЛЬ", "temperature": 0.3,
      "maxTokens": 8000, "contextWindow": 128000,
      "skills": ["code-review", "design-doc"],
      "group": "разработка", "parallel": 2,
      "keyId": "", "orchestrator": "base", "orchestratorRules": "" }
  ],
  "skills": [
    { "id": "code-review", "name": "Код-ревью",
      "prompt": "Найди баги, нарушение стиля, уязвимости. Дай правки с кодом.", "enabled": true },   /* <- ваш промпт */
    { "id": "design-doc", "name": "Дизайн-доки",
      "prompt": "Описывай: контекст → варианты → решение → риски.", "enabled": true }
  ]
}
Сохраните как agents.json. Можно менять только systemPrompt и prompt — остальное опционально, по желанию.
2. Мульти-ключи (авто-переключение при 429)
keys[].apiKeyключ провайдера — подставляете свой
keys[].priorityосновной = 2, бэкап = 1 (при лимите переключится на нижний)
keys[].baseUrlадрес API провайдера
{
  "keys": [
    { "label": "Основной", "baseUrl": "https://api.ПРОВАЙДЕР-1.ком/v1",
      "apiKey": "ВАШ-КЛЮЧ-1", "model": "имя-модели-1", "priority": 2 },
    { "label": "Бэкап", "baseUrl": "https://api.ПРОВАЙДЕР-2.ком/v1",
      "apiKey": "ВАШ-КЛЮЧ-2", "model": "имя-модели-2", "priority": 1 }
  ]
}
При 429 у основного — автоматически переключится на бэкап. Ключи не показываются в UI.
3. Личности-сессии (JSONL)
modecontinue / new_personality / reuse_key
agent_idid агента-личности (из примера 1)
systemPromptOverrideсвоя роль поверх — подставляете свой текст
{"name":"Режим кода","mode":"new_personality","agent_id":"architect","systemPromptOverride":"Работай в режиме code-review, не отходи от кода"}
{"name":"Быстрый чат","mode":"continue"}
JSONL = по одной записи в строку. Каждая строка — отдельная сессия.
4. Оркестратор (параметры)
enabledоркестратор включён вообще (по умолчанию true)
auto_modeлимит контекста считается от окна модели (90%), а не фиксированно
role_drift_checkловить «дрейф» системного промпта, подсовывать напоминание
monitor_latencyписать логи/статистику по задержкам и ошибкам (видно в «Логи» + «Мониторинг»)
auto_save_thresholdкаждое N-е сообщение чата — автосохранение
keep_full_contextне сжимать историю, пока реально не упрётся в окно модели
{
  "orchestrator": {
    "enabled": true,
    "auto_mode": true,
    "role_drift_check": true,
    "monitor_latency": true,
    "auto_save_threshold": 10,
    "keep_full_context": true
  }
}
Это не импортируемый «файл личности», а живые настройки из «Настройки → Оркестратор» — те же поля, просто показаны для справки. Когда выключать: см. «Справка → Как писать» (раздел про оркестратора).

О приложении

AMT Chat — локальный (desktop) ИИ-ассистент: чат с любой OpenAI-совместимой или локальной моделью, генерация медиа и файлов, система агентов/скиллов/личностей, оркестратор качества диалога, лонг-терм-память, безопасные инструменты (файлы/команды), встроенный медиа-плеер и расширяемая система плагинов. Бэкенд — FastAPI (Python), фронтенд — vanilla JS, оболочка — Electron. Все ключи и данные — только у вас локально.

Архитектура

Electron (main.js)
   ├── Python-sidecar: FastAPI (backend/main.py + ai_engine/*) — порт 127.0.0.1:8000
   └── Frontend (frontend/) — vanilla JS, без фреймворков, грузится с http://127.0.0.1:8000/

Бэкенд модули (backend/ai_engine/):    • agents.py         — CRUD агентов/скиллов, seed-ядро, сборка системного промпта    • orchestrator.py   — контроль контекста/роли, умное сохранение, мониторинг    • memory.py         — лонг-терм факты между чатами    • media.py          — генерация картинок/видео/аудио/файлов (любой провайдер)    • tools.py          — песочница ИИ-инструментов (файлы, команды, whitelist)    • web_scraper.py    — реальный веб-поиск (тёплые [[WEBSEARCH:…]] токены)    • keymanager.py     — мульти-ключи, авто-переключение при 429    • extensions.py     — загрузка/управление плагинов    • filegen.py        — генерация файлов (docx/xlsx/pptx и др.)    • sysinteraction.py — системные промпты-предусловия (MEDIA_CAPABILITY и др.)    • tool_registry.py  — единая точка регистрации/выполнения инструментов                          (нативные media/file + внешние MCP)    • mcp_manager.py    — подключение внешних MCP-серверов (STDIO + HTTP)    • desktop_tools.py  — системные действия (окна/браузер/CDP)    • browser_cdp.py    — управление браузером через Chrome DevTools Protocol    • async_utils.py    — безопасный запуск COM-объектов из asyncio (STA)

Что умеет

Чат

  • Любой OpenAI-совместимый API или локальная модель (Base URL + ключ + модель).
  • Выбор агента/скиллов/личности прямо в чате (⋯ → параметры).
  • Вставка картинок/скриншотов/файлов (Ctrl+V) — миниатюры-чипы, содержимое файла попадает в контекст ИИ.
  • Markdown в ответах: заголовки, списки, код, таблицы, ссылки.
  • Голосовой чат: STT (распознавание) + TTS (синтез) через любой провайдер.

Медиа-генерация

  • [[GEN:image|…]], [[GEN:video|…]], [[GEN:audio|…]], [[GEN:file|…]] — ИИ вставляет готовый элемент прямо в сообщение (картинка/видео/аудио/файл, не ссылка-заглушка).
  • Работает с любым провайдером через OpenAI-совместимые эндпоинты (/v1/images, /v1/audio, /v1/videos) — не только OpenAI.
  • Файлы (xlsx/docx/pptx): бэкенд открывает реальный файл и ИИ видит данные, а не «бинарный файл».

Агенты, скиллы, личности

  • Агент = роль + системный промпт + модель/температура + набор скиллов. Ядро: «Веб-агент», «Глубокий аналитик», «Без фильтров» — создаются автоматически при старте, но можно править/добавлять свои.
  • Скилл = готовая инструкция («Как вести код-ревью», «Как планировать») — подключается к агенту или в чате отдельно.
  • Личность = готовый профиль: API-ключ + модель + агенты + скиллы + оркестратор. Можно создать несколько и переключать их как пресеты.

Оркестратор

  • Контроль контекста: сжимает историю (summary), если она реально упирается в окно модели.
  • Контроль роли: ловит «дрейф» (модель забыла системный промпт) и подсовывает напоминание.
  • Умное сохранение: маркирует чат к сохранению по порогу сообщений.
  • Мониторинг: задержка/ошибки/среднее по последним 100 запросам — видно в «Логи» (фильтр «Оркестратор») и в кнопке «Мониторинг» на странице оркестратора.

Память

  • Лонг-терм факты («Пользователь пред��очитает тёмную тему») — сохраняются между чатами, автоматически подставляются в системный промпт.
  • Управляется в «Настройки → Память»: лимит фактов, кнопка «Очистить память».

Инструменты (tool-calling)

  • ИИ может читать/писать файлы, создавать папки, листинг каталогов, запускать команды — только в выбранной «рабочей папке» (проект).
  • Запись и команды требуют подтверждения (auto-approve выкл по умолчанию); команды — только из белого списка. Всё логируется.
  • Нативный tool-calling (вкл. по умолчанию): модель получает JSON-схемы инструментов и сама выпускает tool_calls; бэкенд исполняет их через ToolRegistry и возвращает результат модели (до 5 итераций). Встроенные инструменты: генерация картинок/видео/голоса/файлов.
  • MCP-серверы (см. следующую карточку): внешние STDIO/HTTP-серверы, их инструменты появляются в доступных инструментах модели.

MCP-серверы

  • Подключение внешних MCP-серверов (STDIO-процессы или HTTP-эндпоинты). Их инструменты (префикс mcp____) автоматически появляются в доступных инструментах модели.
  • Переменные окружения сервера шифруются Fernet (mcp_key.key); инструменты MCP по умолчанию требуют подтверждения (auto_approve=False).
  • Управление: «Настройки → MCP-серверы» (добавление/изменение/удаление/тест) + «Хранилище» (список + вкл/выкл).

Медиа-плеер

  • Видео (YouTube/Twitch embeds, прямые .mp4/.m3u8), фото, аудио — воспроизводятся прямо в чате/плеере, fullscreen, фильтры (яркость/контраст/детализация/шум/улучшение).
  • Веб-сайты, блокирующие iframe (X-Frame-Options) — открываются во встроенном frameless-браузере (не отдельное ОС-окно).
  • [[SCREENSHOT:url]] — реальный скриншот страницы через Electron capturePage, не og:image.

Расширения

  • Папка в extensions/ + manifest.json (+ опционально index.js, backend.py) — без перекомпиляции приложения.
  • Управление прямо в приложении: «Справка → Расширения» (вкл/выкл/добавить/обновить список).

Как начать

  1. «Настройки → Подключение»: Base URL + API-ключ (или локальная модель) → «Проверить».
  2. (Опц.) «Настройки → Агенты/Скиллы» — свои агенты/скиллы; «Мульти-ключи» — резервные ключи.
  3. «Чат» — напишите вопрос; «⋯» в шапке чата — выбрать агента/скиллы/личность/промпт.

Где что находится

  • «Главная» — создать чат / группу / личность
  • «Чат» — диалог с ИИ + инструменты + медиа
  • «Генерация» — файлы / фото / видео / голос (прямая генерация)
  • «Настройки» — API, модель, агенты/скиллы, ключи, инструменты, проекты, MCP-серверы, оркестратор, память, темы
  • «Хранилище» — все сущности (агенты/скиллы/ключи/темы/расширения/MCP-серверы) + экспорт
  • «Логи» — события по API/оркестратору/инструментам
  • «Справка» (эта страница) — об app, хаб расширений, гайды «как писать», история обновлений

Расширения

Управляйте расширениями: включайте, выключайте и добавляйте свои. Выключенные не грузятся в приложение. Добавлять можно папку с manifest.json в extensions/ и пересоздать список.

Положите папку с manifest.json в каталог extensions/ (путь показан ниже), затем нажмите «Обновить список».

Как писать: агенты, скиллы, оркестратор, личности, расширения

Всё, что можно расширять в AMT Chat, — это данные (JSON) или папки с кодом (расширения). Никакого перекомпилирования приложения не нужно: кладёте файл/папку, нажимаете «Импортировать» / «Обновить» — и оно уже работает. Ниже — шаблоны для каждого вида.

1. Агент

Агент = роль + системный промпт + (опц.) модель/температура + набор скиллов. Хранится в agents.json (или создаётся прямо в UI: «Настройки → Агенты/Скиллы → Добавить агента»).

{
  "id": "architect",
  "name": "Архитектор",
  "description": "Оценивает решения, даёт trade-offs",
  "systemPrompt": "Ты — senior-архитектор. Оценивай решения, давай trade-offs, всегда показывай риски.",
  "model": "gpt-4o",            /* опц. — иначе берётся активная модель из ключа */
  "temperature": 0.3,          /* опц. 0–2 */
  "maxTokens": 8000,          /* опц. */
  "contextWindow": 128000,    /* опц. */
  "baseUrl": "",              /* опц. — перекрывает Base URL активного ключа */
  "skills": ["code-review", "design-doc"],   /* id-скиллы из этого же файла */
  "group": "разработка",      /* папка для группировки в UI (опц.) */
  "parallel": 1,             /* сколько агентов одной личности работать одновременно (опц.) */
  "keyId": "",               /* привязанный API-ключ (опц.) */
  "orchestrator": "base",    /* "base" | "custom" | "" (опц.) */
  "orchestratorRules": "Мои собственные правила, если orchestrator = custom"
}

Установка: добавьте объект в массив agents файла agents.json и сохраните (или создайте через UI), либо импортируйте целым файлом: «Настройки → Агенты/Скиллы → Импортировать из файла» (JSON с {"agents":[…]}). Ядровые агенты (core_web, core_thinker, core_jailbreak) создаются автоматически при старте и не удаляются — но их промпты/скиллы можно править как обычные.

2. Скилл

Скилл = готовая инструкция, которую можно подключить к любому агенту или использовать отдельно в чате.

{
  "id": "code-review",
  "name": "Код-ревью",
  "description": "Проверяет код на баги и стиль",
  "prompt": "Найди баги, нарушение стиля, уязвимости. Дай правки с кодом, не просто список.",
  "enabled": true,
  "group": "разработка"
}

Установка: то же — массив skills в agents.json или импортом из файла (JSONL = по одной записи на строку). Чтобы скилл реально повлиял на ответ — он должен быть включён (enabled: true) И подключён к активному агенту (поле skills агента) или выбран вручную в чате.

3. Оркестратор (настройка, не «кодинг»)

Оркестратор — это не файл, который вы пишете, а набор параметров (в «Настройки → Оркестратор»):

{
  "orchestrator": {
    "enabled": true,             /* оркестратор включён вообще */
    "auto_mode": true,          /* подстраивать лимит контекста от окна модели */
    "role_drift_check": true,   /* ловить «дрейф» системного промпта, напоминать роль */
    "monitor_latency": true,    /* писать логи/статистику по задержкам и ошибкам */
    "auto_save_threshold": 10,  /* сколько сообщений в чате — автосохранение */
    "keep_full_context": true   /* не сжимать, пока реально не упёрся в окно модели */
  }
}

Когда стоит выключать: role_drift_check — если чат намеренно «переключает» роль (модель должна отклоняться, а не «возвращаться»); monitor_latency — в очень тяжёлых сессиях, чтобы не тормозить; auto_mode — если нужно жёстко зафиксировать лимит вручную. Остальные параметры обычно оставляют по умолчанию.

4. Личность (сессия-пресет)

Личность = готовый профиль: API-ключ + модель + агенты + скиллы + оркестратор. Создаётся в UI («Настройки → Личность (композиция)») или импортом JSONL-файла (по одной строке = одна личность-сессия):

{"name":"Режим кода","mode":"new_personality","agent_id":"architect","systemPromptOverride":"Работай в режиме code-review, не отходи от кода"}
{"name":"Быстрый чат","mode":"continue"}

mode: continue (продолжить текущий чат), new_personality (свой промпт поверх), reuse_key (новый ключ/настройки, та ��е роль).

5. Расширение (код, не данные)

Расширение — папка в extensions/ с обязательным manifest.json. Фронтенд-часть — index.js (обязательный init(ctx)), backend-часть — backend.py (опциональный init(ctx)). Без сборки: кладёте папку, нажимаете «Обновить».

Структура папки
extensions/
  my-ext/
    manifest.json   # метаданные (обязательно)
    index.js        # фронтенд (опц.)
    backend.py      # бэкенд (опц.)
manifest.json
{
  "name": "my-ext",
  "version": "1.0.0",
  "description": "Что делает расширение",
  "frontend": true,
  "backend": false
}

frontend: true — грузить index.js. backend: true — загружать backend.py на сервере.

index.js (фронтенд)
function init(ctx) {
  // ctx.ui.registerPage(id, label, mainId, html)
  const html = `
    <div class="docs-card">
      <h4>Моё расширение</h4>
      <button class="test-btn primary" id="myExtBtn">Клик</button>
      <div id="myExtOut"></div>
    </div>`;
  const main = ctx.ui.registerPage('my_ext', 'Моё ext', 'myExtPage', html);
  document.getElementById('myExtBtn').addEventListener('click', async () => {
    // доступ к бэкенду:
    const r = await ctx.api.fetch('/api/extensions/list');
    document.getElementById('myExtOut').textContent = JSON.stringify(r);
  });
}
backend.py (бэкенд, опц.)
def init(ctx):
    # ctx['tools'] — ToolSandbox (read/write/commands)
    # ctx['extensions_dir'] — путь к каталогу расширений
    print('my-ext backend initialized')
Как добавить расширение
  1. Создайте папку extensions/my-ext/ (путь — на вкладке «Расширения»).
  2. Добавьте manifest.json + нужные index.js / backend.py.
  3. Перезапустите бэкенд (или нажмите «Обновить список», если расширение уже в каталоге при старте).
  4. На вкладке «Расширения» включите его переключателем.

Безопасность

  • Расширения работают в песочнице. backend-код не роняет app при ошибках (лог + skip).
  • Инструменты ИИ — только в разрешённых папках проекта, команды — только из белого списка.
  • Всякое действие инструментов требует подтверждения (если авто-разрешение выключено).
  • Агенты/скиллы — это данные, не код: импортируемый файл не исполняется, просто добавляет промпты.
