# Безопасность AMT Chat

AMT спроектирован так, чтобы ИИ **не мог** нарушить систему без явного
разрешения пользователя.

## Модель угроз
- ИИ-модель (внешний LLM) получает промпты и может просят «выполнить действие».
- Инструменты (tool-calling) — единственная точка, где ИИ влияет на файловую
  систему и команды. Поэтому политика безопасности жёсткая.

## Что может / не может ИИ
| Действие | Политика |
|----------|-----------|
| Чтение файлов | Только в разрешённых каталогах (проект + дефолты) |
| Запись файлов | Только в разрешённых каталогах; по умолчанию требует подтверждения |
| Создание папок | Только в разрешённых каталогах; требует подтверждения |
| Команды (shell) | **Только из белого списка**; по умолчанию список пуст = запрещено |
| Открытие URL | Только `http`/`https`; `file://` и др. отклоняются |

## Авто-подтверждение
- `auto_approve = false` (по умолчанию): перед каждым действием всплывает
  подтверждение (approve/deny) на фронтенде. Бэкенд не выполняет без `approved=true`.
- `auto_approve = true`: действия выполняются сразу (только в доверенном режиме).

## Белой список команд
- Хранится в конфиге инструментов; по умолчанию пуст.
- Запуск вне списка → `code: "whitelist"` + отказ.
- Таймаут (по умолчанию 30 c) предотвращает зависание.
- Запуск в разрешённом каталоге (cwd), вывод обрезается по `max_output_bytes`.

## Разрешённые каталоги
- По умолчанию: папка бэкенда + домашняя папка пользователя.
- При выборе **Проекта** рабочая папка становится первым в списке (приоритет).
- `read_file`/`write_file`/`create_dir`/`list_dir` проверяют `os.path.commonpath`:
  путь должен лежать внутри одного из разрешённых каталогов, иначе `denied`.

## Логирование
- Каждое действие пишется в `tools_log.jsonl` (кто, что, результат, время).
- Просмотр: Настройки → Инструменты → Журнал.

## Что НЕ защищено (ограничения)
- Расширения (`extensions/`) грузятся из вашей папки — это доверенный код.
- Ключи API хранятся в зашифрованном `secrets.bin` (Electron safeStorage / DPAPI
  на Windows). Не публикуйте папку бэкенда.
- Переменные окружения MCP-серверов шифруются алгоритмом Fernet
  (ключ в файле `mcp_key.key`, права 0600). Не публикуйте этот файл.
- Инструменты MCP по умолчанию требуют подтверждения (`auto_approve=False`);
  включение авто-одобрения — ответственность пользователя.
- CORS локальный (localhost); при внешнем развёртывании задайте `AMT_CORS_ORIGINS`.

## Быстрая проверка
```bash
# попытка записи вне разрешённого каталога → denied
curl -X POST localhost:8000/api/tools/execute \
  -d '{"tool":"write_file","args":{"path":"C:\\Windows\\x.txt","content":"x"},"approved":true}'
# → {"ok": false, "code": "denied"}
```
