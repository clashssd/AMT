Do NOT add the lazy MCP block in Task 2 (it belongs to Task 6, which owns the `mcp_manager` dependency and the `_register`/`ToolDef` wiring). When Task 6 lands, it inserts its lazy block immediately above the static `schemas()` line. — Cost if wrong: a Task-2 reviewer might flag the missing MCP block; it's explicitly Task 6's scope, so that's a known deferral, not a defect.
- **T2 tool-loop re-call reuses `client`/`url`/headers:** Verified live code main.py:1273-1281 — the `async with httpx.AsyncClient(...)` block is open when `data = response.json()` runs (line 1320), and `url`/`api_key` are in scope. - **T2 `settings.toolCalling` + `mcp_manager` globals:** `mcp_manager` is a module-level global in main.py (Task 6 sets it). Task 2's tool-loop test calls `call_ai_api("hi", [], settings)` with `mcp_manager` still `None` — the loop must guard `if mcp_manager:` so a None manager is a no-op. Ruling: Task 2's loop body references `mcp_manager` only inside the Task-6 lazy block; the static Task-2 loop uses `tool_registry` (always available) and is `mcp_manager`-agnostic.
- **T4 `MCPManager(data_dir)` in conftest `tmp_backend`:** conftest `tmp_backend` returns a dict with `data_dir` key (verified) — Task 4 tests call `MCPManager(tmp_backend["data_dir"])`. MCPManager reads `AMT_MCP_SERVERS_FILE`/`AMT_MCP_KEY_FILE` env overrides (Task 4 adds them to conftest). Ruling: MCPManager must honor the env-var override for its file paths so tests isolate to tmp; default falls back to `data_dir`.
- **T8 `renderGenInChat` signature:** Plan Task 8 calls `renderGenInChat({kind, prompt:'', result}, assistantEl)` on media tool results. The real `renderGenInChat(item, hostEl)` POSTs to `/api/media/generate` (it generates fresh media, it does NOT render an existing result). Using it for an *already-produced* tool result would re-generate. Ruling: Task 8's media-result rendering must NOT call `renderGenInChat`; instead render the tool result directly (parse the `{"type":"media","kind","data"}` JSON the native handler returns, show image/`<audio>`/file-download inline). The plan's `renderGenInChat(...)` line in Task 8 is wrong — implementer renders the returned data, not a re-generation. — Cost if wrong: double media generation on every native tool result (wasteful + confusing).
- **T1 `tool_registry` import of `media`/`filegen` at handler-call time:** Plan's handlers `from ai_engine import media` inside the async handler (lazy import). This avoids import-cycle at module load. Ruling: keep lazy imports inside handlers exactly as the plan's code shows; do NOT top-level import media/filegen in tool_registry.py.

No other conflicts. Tasks 1,3,4,5,7,9 are self-contained per the scan.
