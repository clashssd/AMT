# История версий — AMT Chat

Краткая, читаемая история релизов. Технический детальный changelog для
отдельных версий хранится в `backend/changelog.json` (используется
автообновлением и экраном «Справка → Апдейты»). Формат — «версия: что
изменилось», по одной строке на изменение, без эмодзи.

Версии идут от старых к новым.

---

## 1.1.18 — текущий (2026-11-29)

  Anthropic, Google, Agnes (с фиксированными default_image_model=
  agnes-image-2.1-flash, default_video_model=agnes-video-2.5), Mistral,

  Runway, Custom.

  SVG-иконок в стиле приложения (frontend/assets/provider-icons/).
- Полный визуальный редизайн раздела «Провайдеры (медиа)»: премиальный
  card-based UI с иконками, capability-бейджами, dialect-чипами,
  подсветкой активного провайдера, hover-эффектами, плавными анимациями
  (frontend/css/providers-med.css).
- Полный CRUD в UI: добавление, редактирование (с заполнением полей),
  удаление, ак��ивация/деактивация провайдеров. Форма редактирования
  заполняется данными существующего провайдера.
- Добавлено поле icon в ProviderStore и ProviderIn.
- Все 63 media/registry/provider теста зелёные.

## 1.1.17 — (2026-11-29)

- Новый раздел «Настройки → Провайдеры (медиа)»: быстро добавлять любые
  провайдеры по шаблону (имя, base_url, API-ключ, модель, capabilities
  image/video/audio, dialect-флаги extra_body_ref/v1_suffix/return_base64/
  videos_mode_body/agnesapi_poll/stt/xi_api_key, default_voice и
  default_*_model). Активный провайдер выбирается в списке и автоматически
  используется медиа-слоем.
- Активный провайдер как fallback для медиа-инструментов: в
  tool_registry._media_cfg добавлен слой — если дедичированные
  imageKey/videoKey/audioKey и глобальный apiKey пусты, берутся
  ключ/адрес/модель активного провайдера (по capability). Ключ шифруется
  Fernet (providers.json, providers.key 0600).
- Provider-neutral dialect: media.py resolve_dialect(base_url) читает
  dialect активного провайдера из providers.json (приоритет), затем
  конфиг-хинты, затем встроенный auto-detect (agnes/elevenlabs). 5
  жёстко-заточенных is_agnes/is_eleven мест заменены резолвером — новый
  провайдер подключается только конфигом/шаблоном, без правки кода.
- Сидирован провайдер agnes (https://apihub.agnes-ai.com, caps image+video,
  agnes dialect). Генерация через него — 100% provider-neutral.
- MCP-генерация тоже подхватывает активного провайдера: нативные
  media-инструменты (generate_image/video/audio/file) и MCP media preset
  совместно используют path _media_cfg — отдельной MCP-логики не нужно.
- REST /api/providers (GET/POST/PUT/DELETE + /{id}/activate + /deactivate),
  Settings.active_provider, UI list+form (frontend/js/providers-med/). 4
  regression-теста (tests/test_provider_store.py). 63 media/registry/provider
  теста зелёные.

## 1.1.16 — (2026-11-29)

- Генерация медиа (image-to-image): устранён ложный 400
  «extra_body.image is not a valid image base64» на agnes-хабах. Протокол
  agnes валидирует `extra_body.image` как «публичный http(s) URL или валидный
  image base64» и отклонял data-URI с префиксом `data:`. Теперь в
  `extra_body.image` отправляется чистый base64 без префикса (обёртка
  снимается дефensively перед вызовом). Стандартный путь
  `/images/edits` (OpenAI-совместимый multipart) не изменён — чистый base64
  применяется только к запасному agnes-диалекту.
- 1 новый regression-тест (tests/test_media_tool_registry.py):
  extra_body.image в agnes-фолбэке — не data-URI, а raw base64.

## 1.1.15 — (2026-11-28)

- Медиа (tool-calling): устранён ложный 400 «Model agnes-3.0-flash is a chat
  model. Use /v1/chat/completions». Когда активный чат-ключ (из 1.1.14)
  использовался как fallback для `generate_image`/`video`/`audio`, LLM-чат-модель
  ошибочно передавалась в `/images/generations` как медиа-модель и провайдер
  её отклонял. Теперь чат-модель НЕ наследуется медиа-инструментами: медиа-модель
  остаётся dedicated (imageModel/videoModel/audioModel) или global (model), либо
  пустой — тогда провайдер сам выберет дефолт.
- Fallback chat base + chat key (no_key-фикс из 1.1.14) сохранён — только
  chat-модель отключена от медиа-слоя.
- 2 новых regression-теста в tests/test_media_active_key_fallback.py
  (чат-модель не доходит до media-слоя; dedicated imageModel доходит).

## 1.1.14 — (2026-11-28)

- Медиа (tool-calling): устранён ложный `no_key` при генерации картинок/видео/
  голоса, когда пользователь работает через мульти-ключ (keys.json) или
  сессионный ключ, у которого отдельный image-ключ не вынесен. Раньше
  `generate_image` возвращал `{"ok":false,"code":"no_key"}` (хотя ключ чата
  явно работал — модель успешно делала tool-calling), и слабая модель затем
  объясняла текстом, почему не может сделать image-to-image, вместо того чтобы
  сгенерировать картинку. Теперь активный чат-ключ (тот, которым модель уже
  успешно делает tool-calling) фиксируется как ПОСЛЕДНИЙ fallback медиа-
  инструментов: dedicated ключ (imageKey и др.) > global ключ (apiKey) > активный
  чат-ключ. Активный base чата приоритетнее generic baseUrl, когда dedicated
  base не задан (LLM-chat endpoint не обязан уметь /images/generations).
- Регрессия: 4 новых теста в tests/test_media_active_key_fallback.py
  (чат-ключ как fallback; dedicated ключ победнее; fallback для video/audio;
  dedicated base не перетирается). Все 64 media/registry теста зелёные.

## 1.1.13 — (2026-11-28)

- Медиа: provider-neutral «второй проход». Код больше не хардкодит
   конкретные хосты/диалекты провайдеров — подсказки провайдеров
   (host-хиты) читаются из конфига: env AMT_PROVIDER_HINTS, файл
   provider_hints.json, иначе встроенный дефолт (только для
   совместимости). Новый провайдер подключается конфигом, а не
   правкой исходников.
- Медиа: image-to-image — честный fallback. Если провайдер НЕ умеет
   редактировать изображение по локальному референсу (нет /images/edits,
   или extra_body требует публичный URL), приложение генерирует
   картинку по текстовому промпту и явно говорит об этом в note, а не
   падает с 400/500. Это исправляет «измени X на фото» у провайдеров,
   у которых image-to-image по data-URI недоступен.
- Медиа: генерация видео — provider-neutral (standard-first). Сначала
   стандартный /v1/videos/text2video для любого провайдера; диалект
   провайдера (из конфига) — только fallback при ошибке. Мultipart для
   video2video собирается вручную, без urllib3 (он не в зависимостях).

## 1.1.12 — (2026-11-28)

- Генерация картинок (image-to-image) теперь **provider-neutral** и работает с
  любыми провайдерами, а не только с агнес: основной путь — стандартный
  OpenAI-совместимый `/images/edits` (multipart). Специфичный для agnes
  протокол (`extra_body.image`) используется только как запасной вариант для
  auto-опознанного agnes-хаба. Ранее ref у не-agnes провайдера падал с 400.
- Убрано скрытое зависимость от urllib3 (не было в requirements): multipart-тело
  для `/images/edits` теперь собирается вручную — код больше не падает там, где
  urllib3 не установлен.
- Добавлен ретрай при транзитных ошибках провайдера («Failed to reach upstream»,
  5xx): после неудачного /images/edits или agnes-запроса делается одна повторная
  попытка через 2 секунды.
- Регрессия: 2 новых теста (provider-neutral ref идёт в /images/edits; agnes
  fallback в extra_body при ошибке edits). Итого 64 media-теста зелёные.

## 1.1.10 — (2026-11-28)

- Генерация медиа через tool-calling: устранён краш «missing 1 required positional
  argument: 'prompt'» и ложный «no_key». Слабые модели иногда вывезли tool-call
  generate_image/generate_video/generate_audio без prompt/text, либо присылали
  null и числа-как-строки. Теперь ToolRegistry.execute() нормализует аргументы
  по схеме (подставляет default, выпиливает null и неизвестные ключи, коэргит
  типы), а обработчики медиа возвращают честный отказ no_prompt/no_text вместо
  TypeError. Для generate_image без prompt подставляется текст сообщения
  пользователя как fallback (зеркалит авто-подстановку [[GEN]]), чтобы
  генерация по референсу не падала.
- Регрессия: 8 новых тестов в tests/test_media_tool_registry.py (нормализация
  аргументов + no-prompt guard), 20 тестов файла зелёные.

## 1.1.9 — (2026-11-28)

- Image-to-image через tool-calling: исправлен 400-краш «extra_body.image must
  be a public http(s) URL or valid image base64». Модель в tool-calling режиме
  сама передаёт ref_image_b64, но часто присылает markdown-обёртку
  (![...](data:image/png;base64,...)) или обрезанный data-URI — из-за чего
  media.generate_image_ref двойно оборачивал мусор и провайдер отвечал 400.
  Теперь новый помощник _clean_ref_base64 вычищает/валидирует base64
  (берёт из аргумента модели, либо из встроенного data-URI в сообщении,
  либо читает прикреплённое фото на диске) и подставляет чистый b64 перед
  вызовом generate_image_ref — либо полностью отключает ref, если чистых
  байтов нет. 13 регрессионных тестов.

## 1.1.8 — (2026-11-28)

- Генерация медиа: ключ/адрес/модель теперь не дают ложного `no_key`, если

- Регрессия: 6-й тест в tests/test_media_tool_registry.py фиксирует

## 1.1.7 — (2026-11-28)

- Генерация медиа через tool-calling: исправлен краш `generate_image` →
  «'dict' object has no attribute 'rstrip'». Обработчики инструментов в
  tool-calling режиме (по умолчанию включён) передавали в media.generate_*
  словарь настроек позиционным аргументом, который связывался с base_url,

  фото/видео/аудио через инструменты снова работает (включая image-to-image
  по референсу: generate_image_ref).
- Регрессия: 5 тестов tests/test_media_tool_registry.py зафиксировали, что
  base_url в media.generate_* — строка, а не словарь.

## 1.1.6 — (2026-11-28)

- Критический фикс: ИИ реально видит прикреплённые фото и файлы (Ctrl+V и
  скрепка). Ранее глобальный список вложений очищался ДО загрузки на бэкенд,

  `_filesForThisMessage` (созданный до очистки), и файлы реально
  загружаются на бэкенд.

## 1.1.5 — (2026-11-28)

- Вложения: ИИ снова реально видит фото и файлы, прикреплённые через
  Ctrl+V и через скрепку. Фото/файл больше не теряется, если сохранённый
  абсолютный путь устарел (приложение пересобрано/перемещено) — бэкенд
  теперь перерезолвит имя файла по актуальной папке вложений (включая
  тайм-префикс {ts}_{name}), а не молча выбрасывает вложение.
- Вложения: пустой или «octet-stream» MIME больше не превращает картинку в
  плейсхолдер — тип угадывается по расширению на фронтенде (при вставке и
  загрузке) и на бэкенде, поэтому фото попадает в vision-ветку и ИИ видит
  пиксели.
- Анти-галлюцинация: если ни одно изо��ражение НЕ удалось встроить (нет
  пиксельных данных), но пользователь ссылается на фото/файл, модель
  получает явную подсказку не выдумывать содержимое и попросить повторно
  прикрепить файл (исправлен случай, когда на XLSX ИИ описывал несуществующее
  фото).
- Перегенерация: для старых сообщений без сохранённых путей теперь
  резолвятся реальные вложения по именам (POST /api/files/resolve), а не
  отправляются голые строки.

- Перегенерация: под ответом ИИ теперь появляются стрелки навигации по

- Вложения: ИИ снова видит фото и файлы при перегенерации и на старых
  сообщениях (сохраняется точный путь _attPaths при отправке;
  /api/files/resolve резолвит имена в пути).
- Редактирование сообщения: новые файлы, добавленные при правке, реально
  загружаются на бэкенд (uploadSingleFile) и сохраняются в _attPaths;

- Vision: даже в tool-calling режиме модель получает короткую подсказку,
  что изображения встроены и она их видит.
- Медиа-анализ: ИИ видит **все** типы вложений — фото, видео, аудио и
  обычные файлы. Видео разбирается в base64-кадры (видит картинку), аудио —
  в транскрипт (STT), файлы — в текст/картинки. Если MIME пустой или
  «octet-stream», бэкенд угадывает тип по расширению (видео/аудио/картинка
  попадут в правильную ветку и ИИ их увидит, а не получит плейсхолдер).

## 1.1.1 (2026-11-27)

- Система slash-команд: 15 команд (`/rag`, `/agent`, `/jailbreak`, `/gen`,
  `/nav_*`, `/help` и др.), overlay на один запрос, комбинация через `+`,
  контекст выбрасывается после выполнения. Реестр в
  `backend/command_registry.json`, парсер в `command_engine.py`.
- Команда `/gen` — генерация медиа/файлов (`photo|image|video|audio|file|combo`),
  image-to-image через референс, маппинг форматов.
- Фронтенд: autocomplete при вводе `/`, кнопка `?` в композере (help overlay),
  подсказки команд.

## 1.0.0 — первый официальный релиз (2026-11-24)

Полный набор функций базового продукта:

- Чат с любой OpenAI-совместимой или локальной моделью: Base URL + API-ключ
  + имя модели, мульти-ключи с авто-переключением при 429 (приоритет или
  round-robin).
- Агенты: роль + системный промпт + модель/температура + набор скиллов. Ядро
  (Веб-агент, Глубокий аналитик, Без фильтров) создаётся автоматически;
  свои агенты — через UI или импортом `agents.json` / JSONL.
- Скиллы: переиспользуемые инструкции, подключаются к агенту или в чате
  отдельно; импортируются тем же файлом.
- Личности: готовый профиль (ключ + модель + агенты + скиллы + оркестратор),
  создаётся в UI или импортом JSONL (по одной сессии на строку).
- Оркестратор: контроль контекста (сжатие истории при переполнении окна),
  контроль дрейфа роли, умное сохранение чата по порогу, мониторинг
  (з��держка/ошибки/среднее по 100 запросам).
- Память: лонг-терм факты между чатами, автоматически подставляются в
  системный промпт; лимит и очистка в настройках.
- Медиа-генерация: `[[GEN:image|…]]`, `[[GEN:video|…]]`, `[[GEN:audio|…]]`,
  `[[GEN:file|…]]` — готовый элемент вставляется прямо в сообщение; работает
  с любым провайдером через OpenAI-совместимые эндпоинты.
- Безопасные инструменты (tool-calling): чтение/запись файлов, создание
  папок, листинг каталогов, запуск команд — только в выбранной рабочей
  папке; запись/команды требуют подтверждения, команды — только из белого
  списка; всё логируется.
- Медиа-плеер: YouTube/Twitch embeds, `.mp4`/`.m3u8`, фото, аудио — в
  чате/плеере, fullscreen, фильтры; сайты, блокирующие iframe, открываются
  во встроенном frameless-браузере.
- Голосовой чат: STT + TTS через любой провайдер, отдельное поле для
  STT-модели.
- Система расширений: папки в `extensions/` с `manifest.json` (+ опц.
  `index.js` / `backend.py`) — без перекомпиляции приложения.
- Справка: отдельная страница — об app, хаб расширений, гайд «как писать»,
  история обновлений.
- Хранилище: просмотр и экспорт всех данных (агенты/скиллы/ключи/темы/
  расширения/чат).
- Логи: дашборд событий по API / оркестратору / инструментам с фильтрами.
- Desktop: Electron + встроенный Python-бэкенд (sidecar, PyInstaller-бандл),
  NSIS-инсталлятор для Windows.
- Темы: готовые + своя (градиент), шрифт и фон, язык интерфейса (RU/EN).
